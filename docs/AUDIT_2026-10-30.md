# PoliticsHub code, UI and delivery audit — 30 October 2026

## Result and current production blocker

The application was inspected from `uunivpt/news-bot`, including the public
frontend, Flask routes, database layer, worker interfaces, existing tests and
command center. The initial workspace had no checkout; the connected repository
was identified through its PoliticsHub branding and deployment.

Neon project `shy-mountain-59394437` returned HTTP 402, **quota exceeded**, during
read-only inspection. Production database reads, admin actions and persistent
newsletter opt-ins cannot be certified while this provider restriction remains.
No billing, plan, production credentials or infrastructure limits were changed.
Source snapshots and the retained public archive remain the intended fallback.

Before this change, live `/api/hindi-feed` requests repeatedly returned
`x-vercel-cache: MISS` and `Vary: Cookie`, despite public cache headers. Flask was
varying even anonymous reads of an empty session. Vercel explicitly refuses to
cache `Vary: Cookie` responses. This defeated the intended CDN protection.

## Fixed flows

| Area | Before | Result |
| --- | --- | --- |
| CDN delivery | Empty-session reads added `Vary: Cookie` globally | Explicitly public, unchanged anonymous responses omit that variation; authenticated/changed sessions retain private behavior |
| Admin listings | Shared public listing URL doubled as a private listing | Command center uses `/api/admin/news`, always authenticated and uncached |
| Article API rendering | A string `article` field was treated like an object | Full article strings render correctly |
| Navigation | Late article responses could replace a newer route | Requests cancel and stale results are ignored |
| Cached startup | Rendering could run before controllers initialized | Boot runs after controller initialization; cached settings route is tested |
| Search | Pending searches kept running; limited controls | Cancellation, race protection, publisher/date filters, short-query recovery and deduplicated pagination |
| Maharashtra | Local route redirected to itself; failed refresh erased good headlines | Static route serves correctly; dated cached headlines survive a failure with an explicit stale label |
| Maharashtra ingestion | Serial publisher requests and repeated failed translations | Bounded parallel refresh, translation retry backoff and bounded translation cache |
| Public feed | Snapshot downloaded alongside every healthy refresh | Snapshot fetched only after API failure; a healthy empty database stays authoritative |
| Snapshot fallback | Outage responses bypassed CDN; concurrent refreshes repeated upstream work | Short public cache lifetime and a single upstream refresh per process |
| DB connections | New connection/long retries per web request | Small bounded client pool, query deadline, limited wait and provider failure backoff |
| Historical articles | Each lookup transferred all live identities | Indexed candidate ID/URL queries and a local archive ID index |
| Archive/sitemaps | Full public rendering work repeated for every archived row | Discovery projection, cached eligible archive metadata and prefiltered live candidates |
| Feed ranking | Prior headlines were tokenized repeatedly; redundant dedupe passes | Cached token sets, safe size-bound pruning and one ranking pass |
| Anonymous rate limiting | Unsynchronized buckets could grow past the cleanup threshold | Atomic limiter with a strict 8,192-bucket bound; platform client-IP handling on Vercel |
| JSON errors | Array/string/malformed JSON bodies could crash handlers | API object-body validation returns HTTP 400 |
| Database errors | Driver errors could surface as generic failures | Sanitized HTTP 503 with a retry hint |
| Owner bootstrap | Documented `ADMIN_USERS_JSON` was unused | Valid hashes bootstrap only an empty table; existing owners are preserved |
| Admin refresh | Dashboard polls reran clustering and recorded their own successful reporting runs | Worker-owned clustering and actual task telemetry; polling does not manufacture runs |
| Admin schema work | Nested reads repeatedly initialized schemas and updated agent definitions | Component setup runs once per database/process, with retry on initialization failure |
| Admin controls | Search races, rapid repeated sign-in and stale settings reads | Debounced/cancelled search, one pending sign-in, fresh settings and disabled controls until loaded |
| Most read | Homepage override disconnected the feature; SSR views were not recorded; ranking reordered by date | Real page-view tracking, atomic update without a full-row read, count-based ranking and no fabricated zero-count list |
| Offline pages | Unvisited article navigation fell back to a misleading homepage | Explicit offline page; bounded service-worker cache excludes tokens, private responses and sensitive paths |
| UI consistency | Static menus linked retired sections; low-contrast secondary consent button | Active desks, useful utility links, contrast correction, source filters and responsive reader controls |

## Added reader features

- **Saved stories:** up to 100 same-origin article links, stored locally only
  after preferences are allowed. Remove/clear and cross-tab refresh are supported.
  Revoking preferences clears the reading list. Saved links are not downloads.
- **Reading controls:** reading-time estimate, standard/large/extra-large text
  and a print layout that removes controls.
- **Sources and official references:** a minimal filterable directory with 12
  references, including election, Parliament, legislation and Gazette records.
  It distinguishes official statements from independent reporting. Directory
  inclusion does not claim automatic ingestion or current source availability.
- **Newsletter readiness:** mail configuration alone no longer advertises signup
  as available when persistent storage cannot be reached. The UI shows temporary
  unavailability without collecting an opt-in it cannot save.

## Verification

Baseline: 156 Python tests and 20 JavaScript/Reel tests passed before edits.
The expanded suite includes real PostgreSQL 18 checks with 100,000 synthetic
records: index plans, bounded connection reuse under concurrent reads, saturation
recovery, query cancellation and sanitized HTTP errors. Tests use no production
database or mail credentials.

The browser audit covers mobile/tablet/desktop widths (320–1,440px), public
navigation, search, ticker controls, load-more, article bodies, save/remove,
consent withdrawal, print/text-size controls, sharing, cached startup, route races,
Hindi language, source filters, admin login/settings/newsroom/logout and offline
navigation. Ads/fonts are blocked for repeatable application checks. Real email
delivery is not attempted. Python tests exercise newsletter opt-in and source
adapter behavior separately.

Reproduce browser checks with:

```bash
pip install -r requirements-dev.txt
python -m playwright install chromium
python scripts/browser_audit.py --serve-fixture --base-url http://127.0.0.1:8010
```

## Capacity and release limits

The code now bounds several common failure modes, but **100,000 concurrent users
have not been load-tested or certified**. A production capacity exercise still
needs representative cached/uncached traffic, real data distributions, CDN hit
ratios, database connection/CPU/egress measurements and failure monitoring.

- Restore database-provider capacity before expecting persistent admin,
  subscription or worker functions to succeed.
- Web workers use at most four client connections each; the shared Neon pooled
  endpoint must still provide the cross-instance connection boundary.
- Rate limiting here is process-local, not a distributed security or billing
  quota. Platform WAF limits and capacity controls remain infrastructure concerns.
- Search preserves full archive behavior; broad substring search can still be
  expensive on a much larger live dataset. PostgreSQL statement deadlines bound
  execution; a future indexed search migration needs representative query plans.
- Existing workers initialize core schema/indexes; Vercel HTTP requests skip core
  migration. Production index rollout cannot be verified while Neon rejects SQL.
- Optional source credentials/permissions, SMTP delivery and Google advertising
  configuration are not manufactured or changed by this code audit.

Rollback is a code revert/redeployment. Saved-story data is browser-local, public
snapshot formats remain compatible, and no destructive schema migration is added.

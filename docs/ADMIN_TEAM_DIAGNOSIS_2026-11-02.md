# Main owner, job roles and live PDF diagnosis

Only `pushkarthawari` receives the primary owner permission set. Existing other `owner` records resolve to Administrator, retaining daily operating controls without staff management. New roles are Viewer (read news), Reporter (create drafts), Editor (create/edit/process), Publisher (editor powers plus Verify/publish/reject), Analyst (news, operational telemetry and reports), and Administrator (all daily operating controls, settings, training and audit history). The main owner alone can generate staff usernames/passwords, assign or restore roles, disable accounts and reset staff passwords. The primary account cannot be changed through staff lifecycle endpoints.

All newly authenticated sessions carry a verifier fingerprint. Each API request rechecks the persisted account and role, so role changes apply immediately, disabled/deleted accounts stop working, and password resets revoke old sessions. Generated secrets are returned once to the owner, shown temporarily in a cleared-on-close/logout dialog, stored only as salted password hashes and omitted from directory/audit/report output. Writes require CSRF and same-origin checks. Legacy signed operating sessions cannot manage staff before a fresh login; the existing phone updater restarts the daemon and rotates its session secret, requiring fresh logins.

System status now downloads a server-generated PDF from fresh connected storage. All saved diagnostic history is the default; optional 30-day, 7-day and 24-hour scopes are available. Reports contain complete source inventory/database aggregates, content completeness, real storage measurements and PostgreSQL durability, available agent run history/totals, audit actions, alerts, failures, publication delivery, scores and event groups. Selected-period details are not silently sampled or capped. News article bodies and credential material are outside an operational diagnosis. Missing measurements are explicitly unavailable. Generation timestamps and period are printed; the file is a point-in-time report. No dashboard snapshot is passed off as live database health. Downloading does not insert synthetic runs or diagnostic history.

The HTTPS phone bridge explicitly allowlists team and diagnosis routes, validates PDF content and supplies attachment headers. Accounts and their role changes remain in the phone PostgreSQL database. Deployment updates the interface and gateway; the immutable backup-preserving Termux updater activates the phone endpoints. Sign in again as the primary owner after updating.

Validation: 389 Python tests with real local PostgreSQL 18; 52 JavaScript tests; 23 reader acceptance checks; 22 admin browser checks including owner hiring, generated credentials, a restricted staff browser, live role changes, access revocation and PDF download. PDF text extraction checked the complete source directory. Synthetic PostgreSQL tests checked persisted staff changes, password-reset revocation and report generation against a 100,000-row archive. No production accounts or articles were modified during tests.
